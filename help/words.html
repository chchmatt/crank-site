Words Crank uses

Crank uses a small set of words, and always in the same sense. If a word here differs from what you'd expect from other tools, the meaning here is the one Crank uses.

People

  • Account. Who signs in. An account has projects.
  • Owner. The person who owns a project (its account holder). Used only in that sense.
  • Operator. The person running and answering the queue at the moment: pressing buttons, answering questions, approving steps. Often the owner, but it could be someone else. The page says "Needs operator" when something is waiting for this person.
    • Why "operator": "player" and "owner" were both tried. "Owner" is about who owns a project; the person watching the queue may be an editor, so Crank calls them the operator.

Work

  • Project. What is being built: one code repository, with its own queue, settings and page.
  • Job. One prompt: one piece of work for a builder, with why, steps, what's left out, when it's done, and tests. Each job has an id like CB-123.
  • Job id. The project's prefix, a hyphen, and the job's number: CB-123, DP-45. Never CB123.
    • Numbers start at 1 in each project and are never reused.
    • The prefix is set in project settings and can be changed at any time. Changing it changes how numbers are shown; the number itself stays the same inside Crank.
    • A job's branch keeps the prefix it was given when the branch was made, even if the prefix changes later, so nothing breaks.
    • With no prefix set, plain numbers are shown.
    • Source: CB-28.
  • Topic. A line of work in a project, such as page or api. Every job belongs to one topic. Each topic has its own runner and its own branch, so topics build side by side. See Topics.
  • Split job. A new job made from the part of a job that couldn't be done yet. Its title ends "(split from CB-11)". See Jobs.

Machines and processes

  • Controller. The program on your computer that runs a project: it picks jobs, starts runners, merges, and talks to the Crank API. Known only by a random id and a name you choose, such as "Controller 1". See Controllers and privacy.
  • Runner. One Claude Code builder working on one topic's job. A project runs up to its set maximum (5 by default).
  • Merge runner. The part of the controller that does the final merge of a topic into its base branch. There is one merge lane per base branch. See Merging.
  • Desktop app. The small Crank app in your system tray. It looks after the controllers for all your projects and shows their live output. It is a thin client: settings live on the website.
  • Crank API. api.crankbuild.com, the one door between your computer, the website and Crank's storage.

Branches (only if you want the detail)

  • Base branch. The branch a topic starts from and merges back into. Usually main; can be another, such as version-2.
  • Topic branch. Where a topic's finished jobs collect before the topic merges. On GitHub it's named crank/<topic>, for example crank/page.
  • Job branch. Where one job is built, named by its id, for example CB-123. Kept on your computer only, except when a job is paused part way (then it's on GitHub as crank/jobs/CB-123).

Runner controls

  • End task. End one runner now, like Task Manager's End task.
  • End all tasks. End every runner now.
  • End after CB-123. Let that runner finish job CB-123, then end it.
  • End all after current jobs. Every runner finishes its current job, then ends.
  • Start runners. Let runners start again after they were ended.
  • Why not "Stop" or "Pause": "Stop" could mean "now" or "at the end of the job". "Pause" sounds like sleep and carry on. Crank never uses either for runners. Paused is only a state of a job or a topic.
  • Source: CB-62, CB-65.

Words Crank doesn't use

  • "Ready" (it's Queued), "Done in part" (see split jobs), "Merge failed" as a job state (it's a note on the topic), "Stop" and "Pause" for runners, "client" and "customer", "landing" (say "merge to main").
