Glossary

The words Crank uses, always in the same sense. If a word here differs from what you'd expect from other tools, the meaning here is the one Crank uses. Within each group the words run A to Z.

People

  • Account. Who signs in. An account has projects.
  • Operator. The person running and answering the queue at the moment: pressing buttons, answering questions, approving steps. Often the owner, but it could be someone else. The page says "Needs operator" when something is waiting for this person.
    • Why "operator": "player" and "owner" were both tried. "Owner" is about who owns a project; the person watching the queue may be an editor, so Crank calls them the operator.
  • Owner. The person who owns a project (its account holder). Used only in that sense.

Work

  • Attended. A job that needs a person at the computer, such as an Azure, DNS or GitHub step or a live push. A runner never builds it on its own; see Runners.
  • Awaiting merge. The status page's filter for Built jobs: finished and tested, not yet in the base branch.
  • Hold all / Release all. One button on the status page. Hold all lets the jobs being built finish and then starts nothing new; the same button then reads Release all, and pressing it lets work start again. It shows as a banner above The list, never as a job's state.
  • Job. One prompt: one piece of work for a builder, with why, steps, what's left out, when it's done, and tests. Each job has an id like CB-123.
  • Job id. The project's prefix, a hyphen, and the job's number: CB-123, DP-45. Never CB123.
    • Numbers start at 1 in each project and are never reused.
    • The prefix is set in project settings and can be changed at any time. Changing it changes how numbers are shown; the number itself stays the same inside Crank.
    • A job's branch keeps the prefix it was given when the branch was made, even if the prefix changes later, so nothing breaks.
    • With no prefix set, plain numbers are shown.
    • Source: CB-28.
  • Merge directly / Open a pull request / Just push. A topic's choice of how its tested work reaches its base. See Merging.
  • Project. What is being built: one code repository, with its own queue, settings and page.
  • Split job. A new job made from the part of a job that couldn't be done yet. Its title ends "(split from CB-11)". See Jobs.
  • Topic. A line of work in a project, such as page or api. Every job belongs to one topic. Each topic has its own runner and its own branch, so topics build side by side. See Topics.
  • Urgent. The one special topic, for fixes that must go first. It always gets its own runner, and while it has unfinished jobs nothing else merges into main.

Job states

Every job has exactly one of these at a time. See Jobs and their states.

  • Building. A runner is working on it now.
  • Built. Its work is finished, tested and in its topic, but the topic hasn't merged into its base branch yet.
  • Cancelled. It won't be built.
  • Merged. Its topic has merged into its base branch (usually main), with this job in it. Only Merged counts as done.
  • Needs operator. It's stopped until you answer, approve or fix something. The reason is in its note.
  • Paused. Someone stopped it on purpose, and it won't start until it is resumed.
  • Queued. Ready: nothing it waits for is unfinished, so it starts as soon as its topic has a free runner.
  • Waiting. It waits for another job (its "after") that isn't finished yet.

Machines and processes

  • Active / Standby / Taking over. A project has one Active controller, which holds the project's lease and builds. Other controllers linked to it are on Standby. One you've pressed Take over on is Taking over until the old one has released.
  • Controller. The program that runs one project on one computer: it picks jobs, starts runners, merges, and talks to the Crank API. Each has its own random id, and is named only on the project settings page by the owner ("Controller 1" until renamed). See The desktop app and controllers.
  • Crank API. api.crankbuild.com, the one door between your computer, the website and Crank's storage.
  • crank. The command Crank installs. The commands and help it prints always say crank ....
  • Desktop app. The small Crank app in your system tray. A thin shell: it starts, watches and restarts the controllers for the projects you tick, and shows their logs. It has no name of its own; settings live on the website.
  • Lease. The 5-minute right to run a project, renewed every 30 seconds by the Active controller.
  • Merge runner. Does the final merge of a ready topic into its base branch. A project has up to its "Max merge runners" (2 by default), one merge per base branch at a time. See Merging.
  • Runner. One Claude Code builder working on one topic's job, named after its topic exactly as spelt: "page runner". A project runs up to its set maximum (5 by default).
  • Self-check. The controller's check every 5 minutes that clears anything wrongly holding work up.

Branches (only if you want the detail)

  • Base branch. The branch a topic starts from and merges back into. Usually main; can be another, such as version-2.
  • Job branch. Where one job is built, named by its id, for example CB-123. Kept on your computer only, except when a job is paused part way (then it's on GitHub as crank/jobs/CB-123).
  • Topic branch. Where a topic's finished jobs collect before the topic merges. On GitHub it's named crank/<topic>, for example crank/page.

Words Crank doesn't use

  • "Ready" (it's Queued), "Done in part" (see split jobs), "Merge failed" as a job state (it's a note on the topic), "Stop" and "Pause" for runners, "client" and "customer", "landing" (say "merge to main").
